# Anvesh Automation Server

The core backend automation engine for Anvesh, built with FastAPI and Playwright.

## 🛠️ Tech Stack

*   **Language:** Python 3.12+
*   **Framework:** FastAPI
*   **Database:** PostgreSQL (with `psycopg` binary)
*   **Automation:** Playwright (Chromium)
*   **Package Manager:** [uv](https://github.com/astral-sh/uv)

## 🚀 Setup & Running

### Requirements
- Python 3.12+
- PostgreSQL 15+
- [uv](https://github.com/astral-sh/uv)

### Installation

1.  **Install Dependencies**
    ```bash
    uv sync
    ```

2.  **Environment Setup**
    Copy `.env.example` to `.env.local` and configure your database credentials.
    ```bash
    cp .env.example .env.local
    ```
    
    Required variables:
    ```env
    DB_HOST=localhost
    DB_PORT=5432
    DB_USER=postgres
    DB_PASSWORD=password
    DB_NAME=lead_scraper
    ADMIN_SECRET=your-secure-secret
    ```

3.  **Start Database (Docker)**
    The `docker-compose.yml` lives one level up, at the repo root (`Anvesh/`), not inside `automation-server/`. Run commands from there, or point `-f` at it.

    Just the database (recommended for local dev — you run the API yourself with `uv` so you get hot-reload and can debug it directly):
    ```bash
    cd ..
    docker compose up -d db
    cd automation-server
    ```

    Or the full stack (Postgres **and** the API, both in Docker):
    ```bash
    cd ..
    docker compose up -d
    ```
    The `automation-server` container mounts this folder as a volume, so it picks up your `.env.local` and reloads on code changes just like running locally.

4.  **Run the Server**
    Skip this if you started the full stack above.
    ```bash
    uv run uvicorn app.main:app --reload
    ```
    API will be available at [http://localhost:8000](http://localhost:8000).

## 🔑 API Keys & Authentication

The API has two separate auth mechanisms:

| Header | Used for | Set via |
|---|---|---|
| `X-Admin-Secret` | Admin endpoints (`/admin/*`, key management) | `ADMIN_SECRET` env var |
| `X-API-Key` | Everything else (`/automation/*`, `/me`, `/me/usage`) | Generated by an admin, see below |

**Admin secret:** defaults to `change-me-in-production` (see `config/settings.py`) if `ADMIN_SECRET` isn't set. Always set a real value in `.env.local` (step 2 above) before doing anything beyond local experimentation — this secret gates all key management, so anyone who has it can mint/revoke API keys.

**API keys** are how end users/apps call the automation endpoints. Each key is tied to a name, a tier (`free`/`pro`/`enterprise` — see [Tier Limits](docs/api/overview.md#tier-limits)) that caps its monthly lead quota, and optionally an expiry. The raw key is only ever shown once, at creation — the server stores just a SHA-256 hash of it.

**1. Create an API key** (admin-only, needs `X-Admin-Secret`):
```bash
curl -X POST http://localhost:8000/admin/keys \
  -H "X-Admin-Secret: your-secure-secret" \
  -H "Content-Type: application/json" \
  -d '{"name": "My App", "tier": "free"}'
```
Copy the `data.key` value (e.g. `anv_abc123...`) from the response — you won't be able to retrieve it again. If you lose it, revoke the key and create a new one.

**2. Use it to call the API:**
```bash
curl http://localhost:8000/me \
  -H "X-API-Key: anv_abc123..."
```
or to kick off a scrape:
```bash
curl -X POST http://localhost:8000/automation/start \
  -H "X-API-Key: anv_abc123..." \
  -H "Content-Type: application/json" \
  -d '{"industry": "restaurants", "locations": ["Mumbai"], "limit_per_location": 10}'
```

See the full [Keys API](docs/api/keys.md) and [Automation API](docs/api/automation.md) docs for every endpoint (listing/revoking/deleting keys, checking usage, task status, CSV export, etc.), or browse the interactive docs at [http://localhost:8000/docs](http://localhost:8000/docs) once the server is running.
